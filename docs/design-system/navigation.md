# Navigation and protected view lifetimes

`index.tsx` captures/scrubs setup-link credentials once before StrictMode or Framework7 initializes. It mounts exactly one `NativeAppProvider`, then App's auth/role/passkey/section gates. Setup credentials never become application routes.

Authenticated staff mount `components/shell/StaffShell.tsx`; portal identities mount `PortalShell.tsx`. They are mutually exclusive. Each protected workspace owns a Framework7 View/router and native Page/Navbar/ToolbarPane transitions. Primary tabs and the tablet sidebar feed that router. There is no independent React Router or second pushState navigation stack. Protected workspace keys include principal/role/section; a changed identity destroys all cached pages/sheets rather than hiding them.

Staff hash routes use `#!/home/`, `#!/weeklyMarks/`, `#!/dashboard/`, `#!/companyCalendar/`, `#!/archives/`, `#!/settings/`, `#!/portalAccess/`, `#!/accountSettings/` and `#!/members/:encodedId/`. Portal routes use `#!/portal/`, `#!/portal/calendar/`, `#!/portal/squad/` and `#!/portal/account/`. Hash routing preserves the existing static-host SPA contract. Identifiers are encoded; malformed/unknown paths are rejected. Company-only destinations do not enter Junior workspaces; Section Settings navigation is captain/admin-only, with Account available to all staff. Incoming forbidden routes are validated before initial router matching.

`navigation.ts` is the staff destination/title/permission map. Portal destinations derive from current scoped server data. A hidden tab is not authorisation: real services/RLS/Edge gates remain authoritative. Ordinary members never gain individual teammate statistics. Demotion/revocation redacts cached portal content. Role checks refresh on focus, visible resume, token refresh and a bounded interval; async request generations reject obsolete results. Staff data returns no previous-scope snapshot while a new scope loads.

Feature content consumes current context props inside routed Pages, avoiding captured stale datasets. Native page lifecycle makes outgoing content inert. Entry updates document title and focuses the page heading without scrolling; subsequent field/data renders must not steal focus. Framework7 owns its page/history/scroll relationship. Roster filters are restored per section through the existing filter storage contract. This implementation uses a single routed stack per protected workspace, not independent persistent Views for each primary tab.

Unsaved navigation uses the existing shared hook: tabs/sidebar, detail Back, browser Back/Forward, section changes, logout and unload require a deliberate decision. Router beforeLeave holds resolve/reject callbacks. Canceling browser Back restores the browser cursor; confirming proceeds. Meeting-date changes and member-editor drafts have their own canonical confirmations. Test Stay, Leave and Forward, not only a happy-path click.

The browser owns its edge-back gesture and scrolling. Framework7's conflicting swipe-back is disabled. Browser route history contains paths/identifiers only and is not a persistent member-data cache. No offline queue, protected response cache or browser history payload is added.

At section-selection/switch boundaries, the incoming address is reset to `#!/home/` before mounting the new protected View. Normal in-workspace history remains Framework7-owned. Data refresh and local settings callbacks capture their scope object, not just its identity string: a callback from Company → Junior → Company must not affect the second Company lifetime. Request generations additionally reject superseded fetches within one lifetime.
