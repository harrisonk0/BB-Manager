## Baseline findings that integration must address

`hooks/useAppData.ts` currently clears data after logout via effect, but asynchronous `refreshData` can resolve after that clear and has no generation/principal guard. `hooks/useAuthAndRole.ts:loadUserRole` likewise has no stale-response ownership check. These are observed baseline code risks, not proof of a reproduced exploit. New cached navigation must not amplify them. Independent tests should defer fetch/role promises and verify that old results cannot update the new security context. If those hooks are amended, keep changes narrowly scoped and review separately from visual refactoring.

`PortalHomePage` refreshes on focus and every60seconds and clears summary/events on failure. Its navigation currently stays in React memory. Moving to retained Framework7 pages must preserve or improve this revalidation and clear any old own-squad dataset after demotion/transfer/reset, rather than relying on hidden navigation controls.

`PortalAccessPage` has provision/reset through the same existing backend `provision` action, with old-user deletion performed server-side. There is no separate standalone revoke UI/API in baseline. Preserve deletion/reset revocation instead of introducing an unreviewed endpoint to satisfy a label in the request.

The latest `company_portal_summary` SQL (member-rank migration) intentionally gives ordinary boys teammate names/leadership/ranks and Company squad aggregates, **no teammate statistics**. Activated current leaders receive individual dated marks only for their current Company squad. “Historical” does not authorize all archived sessions or other-squad former members. Do not fetch staff tables to enrich portal charts.
