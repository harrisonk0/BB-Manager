## Standard page anatomy

Use `PageContainer` → optional contextual Back → `PageHeader(title, description, actions)` → optional `Toolbar(search, filters, context)` → primary task/content sections → optional `SaveBar`. Inline status belongs next to the task that produced it; page loading/error/empty states keep location and navigation context.

Titles and primary actions align to the same gutters on every viewport. Put secondary filters in a named sheet/disclosure when space requires it, and show active filter/count state outside it. Use descriptive labels in the primary flow. A calendar grid, marks editor, recovery form and report are different tasks; they should share tokens and control behaviour without being forced into identical card grids.

## Skill application

The installed frontend-app-builder quality criteria informed C01–C07, C14–C16: typography, hierarchy, density, container discipline and icon/asset consistency. Its implementation/image-concept steps were not applied because this request explicitly limits work to audit and strategy.

Vercel Web Interface Guidelines informed C08–C20, including zoom, labels, native controls, focus, URL state, long content and reduced motion. The React skill's `bundle-conditional`, `async-parallel` and hook/render guidance informed C21. `useAppData` already starts roster/settings concurrently, and `fetchArchivedBoys` loads archive members/marks concurrently; keep those practices. Server rendering, server actions and Next.js-specific recommendations do not apply to this browser SPA.
