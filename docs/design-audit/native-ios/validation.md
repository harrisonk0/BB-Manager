## Design critique and iteration

1. **Initial concepts looked like a web dashboard.** The user explicitly rejected the first comparison. Reworked the reference around system large-title navigation, grouped native lists, clear segmented selection and focused sheets. The [superseded board](../../../prototypes/native-ios/concepts/initial-directions.png) remains labelled as such. The [revised direction board](../../../prototypes/native-ios/concepts/revised-directions.png) explores genuinely different roster, agenda and dark task compositions; it is an illustration, not approved product copy.
2. **Three unrelated page idioms would persist without shared anatomy.** Built the same title, list, icon-button, settings-row, segmented and sheet families across staff, personal portal and leader. Removed repeated per-member action bars. Restricted translucency to navigation and modal separation; opaque data remains legible.
3. **The first leader hierarchy put secondary reporting ahead of tonight’s people.** Moved the dated roster immediately after the compact summary on phones/tablets. Trends and standings follow. Desktop can show chart/standings together above the full table. Restored average and per-member attendance as readable data, alongside totals and all recorded dates. The summary, chart, roster and history now derive from consistent fixtures.
4. **Tablet density and tiny supporting labels needed attention.** Removed 11px sidebar typography, kept 44px controls and allowed the tablet report panels to stack until enough width exists. Long names wrap. At 320px the marks avatar yields space to name/input; Junior fields get a dedicated second row. Main document overflow is not hidden with global clipping.
5. **Automated inspection caught label/contrast defects.** Roster buttons now expose their visible content naturally; account labels include visible initials; chart names include the visible values/dates. Darkened several secondary labels and absent-avatar text. Re-ran the full matrix after corrections; zero configured axe violations remain in the captured states.
6. **Interaction review found draft and focus hazards.** Same-section selection now preserves pending marks; historical review opens the dated marks workflow instead of a disconnected pretend edit. Date changes protect drafts. Selecting filters preserves focus. Browser Back closes open sheets and releases the scroll lock. Score Enter advances to the next enabled field. Invalid filtered rows can be revealed on Save. Saving disables entry mutation, and failed saves retain a retryable draft.
7. **The short member editor wasted space.** A full-height form left a large unused lower surface. Changed the short form to a fitted bottom sheet, retained full-height history and made its body flex so the footer stays at the bottom. Added keyboard-inset enhancement, plus focused-task and failed-save captures.
8. **Reference versus actual implementation was inspected directly.** Viewed the revised four-screen reference and rendered screenshots at all seven requested widths, including full-content pages and representative overlays. Retained the system type hierarchy, grouped rows, opaque content and quiet functional tabs. Deliberate changes: official intact brand assets replace generated logos; valid Company years replace generated Year 7 examples; genuine derived fixture totals replace image-invented statistics; haptic controls are omitted; the dated mobile roster precedes secondary charts; touch targets are at least 44px. These changes follow the user’s functionality/accessibility constraints, not screenshot imitation.

The first 390px captures (`*-390-first.png`) are retained as iteration evidence, not the final design. Some captured an in-flight arrival fade; final screenshots wait for settled rendering. A correct render alone was not treated as design approval.

## Functional verification

The recorded interaction assertions cover search, per-tab preservation and browser history; stable filter focus, modal containment/Escape/trigger restoration; local member creation/editing; decimal scores and keyboard advancement; unload-listener registration and date discard protection; current-section draft preservation; present blank → zero; absent/unrecorded; Junior maximum/precision and calendar exclusion; failed-save draft retention/retry; own-squad rows and ordinary-boy report exclusion; chart/date selection and all weeks; Back closing a sheet without leaving scrolling locked; reduced motion and solid navigation.

These are local presentation/interaction tests, not security or database tests. The harness removes unload listeners only between independent fixture navigations to prevent MCP’s browser-dialog state from blocking subsequent cases. Actual date-discard protection remains exercised, and listener registration is asserted. It does not claim to have manually approved the browser’s leave-page prompt on iOS.

`npm run typecheck`, the isolated prototype build, and the normal application build pass. The normal build retains its existing large-chunk warning. No package manifest/lockfile, production component/style, service, schema, auth or permissions file is changed. Existing backend-mutating E2E/SQL tests were not invoked for this isolated visual study.

## Remaining review boundaries

- Physical iPhone Safari/standalone, San Francisco rendering, safe-area hardware insets, keyboard avoidance, VoiceOver, installed launch/resume and browser gestures remain unverified. No iPhone screenshot or hardware certification is implied by a 390px Chromium capture.
- Production data volume, page-family loading/error states, text-only enlargement/400% reflow, larger content preferences, Firefox/WebKit and print output remain migration gates. The prototype permits zoom and demonstrates reduced motion/contrast foundations; it does not close every audit item.
- Dark appearance, real passkeys/push/logout, durable drafts/offline data, imports/PDF/archive rollover and full administration are not live integrations. The Junior marks task is interactive; aggregate Junior reporting needs a dedicated adapter. Detail/filter URLs are future route work.
- The staff example is a synthetic management workspace, not evidence that every officer/captain/admin authorization gate has been retested. Role filtering illustrates the intended presentation only.
- The user has not yet approved Assembly. Review the working task flows and actual screenshots before any full production migration. The roadmap preserves all original verified audit defects as mandatory acceptance criteria.
