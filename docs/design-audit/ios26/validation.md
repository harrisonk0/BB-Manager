# Visual and interaction validation

The official Playwright MCP rendered real, built React applications. Captures use a stable static build rather than Vite HMR, which otherwise reacts to evidence files written inside its project. Screenshots were inspected individually at key phone states and in comparison sheets across every target width; detected problems were corrected and the affected states captured again.

| Evidence set | Capture states | Workflow scenarios | Assertions |
| --- | ---: | ---: | ---: |
| chromium | 140 | 34 | 90 |
| webkit | 140 | 34 | 90 |
| webkit-phone | 20 | 24 | 62 |

All stored capture states have zero recorded page exceptions, configured axe WCAG A/AA violations, detected document overflow and measured enabled visible controls below the 44px product target. This is scoped automated evidence, not a complete WCAG certification. Switch and sheet-handle hit areas also need consideration beyond glyph/track geometry; keyboard and touch checks exercise them.

The full desktop-engine comparison covers both variants at **320, 375, 390, 430, 768, 1024 and 1440px**, height 844px. Each width includes roster, filter sheet, member detail, dirty Marks with Save visible, focused numeric input, Squad report, Settings, workspace sheet, member editor and destructive confirmation. The additional iPhone 13 descriptor pass captures the same ten states for each variant at 390px with touch emulation and device pixel ratio 3.

**Playwright WebKit and iPhone emulation are not physical iPhone Safari or an iOS simulator.** The descriptor changes viewport/touch/user-agent behaviour; it does not supply Apple's installed font files, native keyboard, OS gestures, Home Screen storage or compositing. A focused-input screenshot does not show a real software keyboard. Physical Safari and Home Screen review remains required.

## Working interactions

The recorded scenarios cover current-task skip navigation; modal Tab/Shift+Tab containment and Escape dismissal; search retention across tabs; scoped filtering and restored focus; accessible sheet detents; adding an eligible NCO and confirmed deletion; invalid/decimal scores; three attendance states and present-blank-zero; failed save/draft retention/retry; Junior behaviour limits and correct error-field focus; empty-date prevention; dirty-date protection; motion/solid-material preferences; keyboard-operable switches; contextual squad back navigation; own-squad leader presentation; and ordinary-portal presentation. Touch-emulated checks additionally tap outside the visible switch track to exercise its expanded hit area.

See the actual assertions in [Chromium](../../../prototypes/ios26/evidence/chromium/interactions.json), [WebKit](../../../prototypes/ios26/evidence/webkit/interactions.json) and [touch emulation](../../../prototypes/ios26/evidence/webkit-phone/interactions.json). Role checks verify synthetic presentation only; they do not validate or replace production server authorisation.

## Critique and iteration

- Initial Framework7 view composition left inactive tab content in layout. Correct tab CSS/lifecycle and per-view scoping now keep the intended screen active; touch activation uses `onTabShow`, not an assumed React click callback.
- An inherited button width compressed a member profile name. The profile action now has an intrinsic width and the detail hierarchy stays readable at 320px.
- The Save accessory originally sat under Framework7's view stacking layer. Its explicit layer and reserved scroll space now keep the action usable above navigation.
- Sheet detents initially exposed too little usable content. Content height/scroll containment and explicit Expand/Compact controls were corrected. Native+ uses a full panel on tablets rather than applying a phone fraction there; its phone-only bottom fill is removed from floating tablet panels.
- The 320px member form put its completion action below the visible fields. Add/Save now lives in the sheet header, remaining reachable while the form scrolls.
- Framework7's Toggle needed React state synchronisation and a visible-to-AT native checkbox. The real input now remains keyboard accessible with a 44px hit area and a visible label focus ring. Native+ extends the hit area without enlarging its native-size track.
- Framework7's disabled button styling did not supply native disabled semantics. The adapter now supplies both semantics and an action guard.
- Closed Framework7 sheets retain the framework’s hidden display state, preventing off-screen tab stops. Sheets contain keyboard focus, restore it after removal and select their initial full detent before the next paint. Skip navigation focuses the active application main without changing the task.
- Search semantics, dialog naming, focus origin/restoration on Safari-style pointer focus, valid list structure and field-specific Junior validation associations were corrected.
- Generic/over-decorated card compositions were avoided: roster grouping supplies the structure, report metrics remain compact, and glass stays in navigation/functional layers.

The visual review found no remaining obvious clipping or inconsistent component family in the stored core captures. This does not close the original production audit: its defects remain mandatory migration gates.

## Performance and compatibility limits

[Per-entry bundle evidence](../../../prototypes/ios26/evidence/bundle.json) includes each entry and shared imports; [the timing probe](../../../prototypes/ios26/evidence/chromium/performance.json) uses 15 changes to the same 18-member fixture in an unthrottled Linux Chromium VM. These are not full network-transfer, INP or physical iPhone measurements. No human task-speed study or 100-member device profile was performed.

The live website-glass page was rendered in WebKit and its computed blur/saturation fallback inspected. No advanced SVG refraction is shipped. The Light presentation was also checked under a system dark preference without configured axe findings; a full dark theme is not implemented.

Root and prototype type-checks and both Vite builds pass locally. The production TypeScript project excludes the isolated experiment; a dedicated prototype CI job installs its own lockfile and checks/builds it separately. Production package/lockfile, Tailwind 3, UI, authentication and backend contracts are unchanged. No live mutation tests, deployment over production or merge were performed.

Real-device acceptance still includes VoiceOver, text enlargement/reflow, keyboard occlusion, safe-area/status-bar combinations, touch drag/scroll feel, Safari versus standalone launch/resume, slow/offline launch and thermal/GPU performance. The prototypes have manifests but no service worker or durable offline writes.
